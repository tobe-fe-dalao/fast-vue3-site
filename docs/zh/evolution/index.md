# 架构演进概述

Fast Vue3 经历了从 **Polyrepo（单仓库）** 到 **Monorepo（多包仓库）** 的完整架构演进过程。

## 演进时间线

```
2022 ~ 2024          2025.Q1              2025.Q2 ~ 至今
────────────        ────────────         ────────────────
 Polyrepo 阶段        归档阶段              Monorepo 阶段
 单仓单应用           polyrepo 分支         main 分支重建
 Vite + Vue3          保留历史              多应用工程平台
 标准化优化           归档完成              5 套 UI 生态
```

## 两套架构并存

| 分支 | 架构 | 描述 |
|------|------|------|
| `polyrepo` | Polyrepo | 历史遗留架构，已归档 |
| `main` | Monorepo | 新架构，持续演进 |

`polyrepo` 分支作为历史参考保留，不再接受新功能开发。`main` 分支承载所有新工作。

## 为什么要迁移

Polyrepo 阶段的主要痛点：

1. **版本碎片化** — 所有依赖版本分散在单个 `package.json`，难以统一升级
2. **无法复用** — 如需支持多套 UI，必须复制整个项目
3. **工程配置重复** — ESLint、TypeScript、Vite 配置每次都要重写
4. **缺乏包边界** — 所有代码在 `src/` 下混合，职责不清晰
5. **可扩展性差** — 添加新的技术方案需要分叉仓库

Monorepo 解决的核心问题：

- **统一版本管理** — pnpm workspace catalog
- **共享基础设施** — `packages/*` 一次编写，所有应用复用
- **可扩展性** — 新增 UI 生态只需 `apps/` 下新增一个应用
- **清晰边界** — 每个包职责单一，接口明确
